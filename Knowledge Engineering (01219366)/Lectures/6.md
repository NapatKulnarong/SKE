## 1. Recap — triples and prefixes

Knowledge graphs are **triples**: `[subject]  predicate  [object]`.

Prefix + local name = the entity, e.g. `ex:` + `Alan` → `ex:Alan`.

Graph on the slide:

```
[ex:Alan]          ex:studiesAt    [ex:UniversityA]
[ex:Bob]           ex:studiesAt    [ex:UniversityA]
[ex:UniversityA]   ex:locatedIn    [ex:Bangkok]
[ex:Alan]          ex:studies      [ex:ComScience]
[ex:Bob]           ex:studies      [ex:Linguistics]
[ex:ComScience]    ex:partOf       [ex:FacultyOfScience]
[ex:Linguistics]   ex:partOf       [ex:FacultyOfHumanities]
```

*(Slide also writes `ex:part of` on the ComScience row — same relation as `partOf`.)*

You query by matching **this graph pattern**, not table rows.

## 2. What SPARQL is

**SPARQL** = SPARQL Protocol and RDF Query Language.

It retrieves (and can manipulate) data in RDF KGs by **patterns of relationships**, not SQL’s rows-and-columns.

The slide lists what it can do:

- select specific data
- **variables** for unknown values (`?x`)
- filter and sort
- join / combine information (extra triple patterns)
- aggregate: **COUNT, SUM, AVG**

## 3. Wikidata

Free collaborative KG run by the Wikimedia Foundation. Entities: people, places, organisations, works, science, events.

Wikipedia is prose for humans. Wikidata stores **structured statements** a machine can query.

## 4. Prefixes: `wd`, `wdt`, `p`, `ps`, `pq`

| Prefix | IRI idea | Use |
| --- | --- | --- |
| `wd:` | `http://www.wikidata.org/entity/` | **entity** (item) |
| `wdt:` | `http://www.wikidata.org/prop/direct/` | **direct** predicate (simple fact) |
| `p:` | statement | the **statement node** (when you need extras) |
| `ps:` | statement’s **main value** | the office, the prize, … |
| `pq:` | **qualifier** | start time, end time, … |

**URI shape**

- Entities: `Q` + number — `Q869` Thailand, `Q1861` Bangkok
- Predicates: `P` + number — `P36` capital

**Labels** (human names, not the ID): `en` Thailand / Bangkok; `th` ไทย / กรุงเทพ

### Direct fact vs full statement (Obama)

Slide example: Obama (`wd:Q76`) position held (`P39`) President of the United States (`wd:Q11696`).

```
Obama  --p:P39-->  [Statement]
                      | ps:P39
                      v
              President of the US
                 /            \
         pq:P580 2009     pq:P582 2017
```

| Prefixes you use | What you said |
| --- | --- |
| `wd:` + `wdt:` | “Obama **is** President” (truthy / direct) |
| `p:` + `ps:` + `pq:` | “Obama **was** President **from 2009 to 2017**” |

Use `wdt:` when one cell is one value. Use `p`/`ps`/`pq` when the fact has **start/end** (or other nested fields).

## 5. Labels, LIMIT, ORDER BY

**Readable names** (Wikidata Query Service):

```
SERVICE wikibase:label { bd:serviceParam wikibase:language "[AUTO_LANGUAGE], en" . }
```

*(Slide text drops a `[` in `"AUTO_LANGUAGE], en"` — the working form includes `[AUTO_LANGUAGE]`.)*

- `[AUTO_LANGUAGE]` — UI language  
- `en` / `th` — English / Thai  
- Variable `?x` gets a sibling **`?xLabel`**

**How many rows:** `LIMIT 20`, `LIMIT 100`

**Sort:** `ORDER BY DESC(?x)` or `ORDER BY ASC(?x)`

## 7. Do-it-yourself tasks

Write and run these on the Query Service (skills the tasks force: geo, `FILTER`, `OPTIONAL`, `p`/`ps`/`pq`, dates, `ORDER BY`, `LIMIT`):

1. Airports in Asia + coordinates; **map** view.

3. Museums worldwide; genre and established date **optional**.
4. Scientists with a Nobel **after 2000**; name, nationality, prize, year; sort year **earliest→latest**.
5. Mountains in Thailand, elevation **> 1000 m**; name, elevation; province **optional**; sort elevation high→low.

Task 6 is the Obama-pattern query: `p:` position + `pq:` start/end, not only `wdt:`.

---

## Takeaways

- SPARQL matches **triples** with `?variables`, not SQL tables.
- Wikidata: `wd:` item, `wdt:` simple fact, `p`/`ps`/`pq` when the fact has **qualifiers**.
- `SERVICE wikibase:label` fills `?xLabel`; then `ORDER BY` / `LIMIT`.
- Direct `wdt:` loses start/end; PM/president questions need the statement node.
