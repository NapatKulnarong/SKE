## 1. Asserted vs inferred

A reasoner’s main service: test whether class A is a subclass of class B. Running that on every pair **computes the inferred class hierarchy**.

| Tree | Who built it |
| --- | --- |
| **Asserted** | you, by typing SubClass Of |
| **Inferred** | the reasoner, by subsumption |

Computing that tree = **classifying** the ontology (also checks inconsistencies).

- Protégé 4: Reasoner → **Classify…**
- Protégé 5: Reasoner → **Start reasoner**

---

## 2. Why classify with a reasoner

Benefit of OWL-DL: the machine maintains **multiple inheritance**. In large ontologies you cannot reliably keep “this class has many parents” by hand. The reasoner adds inferred subclasses (pizza example: several topping kinds appear **under** `VegetarianTopping` without you dragging them there). That keeps the ontology maintainable and cuts human error.

---

## 3. Primitive classes get no inferred children

> A reasoner will **never** place classes as subclasses of a **primitive** class (no necessary-and-sufficient conditions).

Why: matching φ is enough to enter A only when φ is **sufficient**. SubClass Of is necessary only — “members of A obey φ” does not mean “whoever obeys φ is in A.” Only **Equivalent To** (defined) classes collect inferred children.

## 4. MyPizza and Open World

Build `MyPizza` ⊑ `NamedPizza` with

```
hasTopping some AsparagusTopping
hasTopping some MushroomTopping
hasTopping some SpinachTopping
hasTopping some MozzarellaTopping
```

Those fillers are vegetarian. **MyPizza still does not classify under VegetarianPizza.**

VegetarianPizza on the slide is **defined**, e.g. Pizza and `not (hasTopping some FishTopping)` and `not (hasTopping some MeatTopping)` — or an `only` veg toppings form.

**Open World Assumption (OWA / OWR):** unsaid is **unknown**, not false. Until you say MyPizza has **no other** toppings, it **might** still have pepperoni. Missing meat ≠ no meat.

---

## 5. Closure axiom

To classify MyPizza as VegetarianPizza, add a **closure axiom** on `hasTopping`: a **universal (`only`)** whose filler is the **union of the existential fillers**.

```
hasTopping some AsparagusTopping
hasTopping some MushroomTopping
hasTopping some SpinachTopping
hasTopping some MozzarellaTopping
hasTopping only (AsparagusTopping or MushroomTopping or MozzarellaTopping or SpinachTopping)
```

Protégé: type `only` by hand, or right-click an existential → **Create closure axiom**.

---

## 6. `only` without `some`

A common error: MyPizza ⊑ NamedPizza with **only**

```
hasTopping only (Asparagus or Mushroom or Mozzarella or Spinach)
```

and **no** `some`. Universal includes **empty**: NamedPizzas that have only those toppings **or NamedPizzas with no toppings at all**. Pair `only` with `some` when the thing must exist.

## 7. Exercise — salad inferred hierarchy

![[7_salad_ontology.png]]

![[7_salad_restrictions.png]]

**Output format (exam)**

| Parent Class | Inferred subclasses |
| --- | --- |
| ClassA | ClassB, ClassC, ClassD |

**Disjoint (same row)**

- Dressing, Meat, Topping, Vegetable, Egg  
- CreamyDressing, LowCalDressing  
- Beef, Chicken, Seafood, Pork  
- Bean, HerbVeggies, RootVeggies, LettuceVeggies, Grain, MarrowVeggies, CruciferousVeggies  

`MeatTopping` ⊑ Topping, disjoint from `Meat`. Properties: `hasDressing`, `hasVeggie`, `hasMix`. `Salad` (primitive) has `hasDressing some Dressing` and `hasVeggie some Vegetable` — every salad inherits those.

**Method:** only **Equivalent To** parents can gain inferred children. A child C ⊑ defined D if C’s axioms **force** every C-instance to satisfy D (use disjoint + `only` to close). `some` does not close. Primitive classes (BeefSalad, ChickenSalad, …) never appear in the Parent column.

### Defined parents — equations then inferred children

Assume truncated slide text: Super Veggie = `Salad and (hasVeggie min 4 Vegetable)`; Mix Veggie = `Salad and (hasVeggie min 3 Vegetable)`.

**MixVeggieSalad** ≡ Salad ⊓ `hasVeggie min 3 Vegetable`  
Answer: **SuperVeggieSalad, GreenSalad, EggSalad, HealthySalad**  
(min 4 ⇒ min 3; min 3 LettuceVeggies ⇒ min 3 Vegetable; Egg’s three disjoint `some` veg ⇒ min 3; Healthy already `min 3 Vegetable`.)

**SuperVeggieSalad** ≡ Salad ⊓ `hasVeggie min 4 Vegetable`  
Answer: *(none of the named salads force min 4)*

**VegetarianSalad** ≡ Salad ⊓ `not (hasMix some Meat)` ⊓ `not (hasMix some MeatTopping)` ⊓ `hasVeggie some Vegetable`  
Answer: **EggSalad**  
(`hasMix only Egg` + Egg disjoint Meat/MeatTopping + inherited some Vegetable). Mix/Super/Green are **not** closed on `hasMix` (OWA — could still have meat). Seafood/Beef/… have meat.

**ProteinSalad** ≡ Salad ⊓ `hasMix some Chicken` ⊓ `hasMix min 3 Meat`  
Answer: *(none)* — ChickenSalad is only `some Chicken` (not min 3); PowerMeat has Beef+Pork+MeatTopping (MeatTopping ≠ Meat, and no Chicken).

**GrainSalad** ≡ Salad ⊓ `hasMix some Meat` ⊓ `hasVeggie min 4 Grain`  
Answer: *(none)* — nobody forces min 4 Grain.

**HealthySalad** ≡ Salad ⊓ `hasMix some Egg` ⊓ `hasDressing only LowCalDressing` ⊓ `hasMix only (Chicken or Egg or Seafood)` ⊓ `hasVeggie min 3 Vegetable`  
Answer: *(none)* — EggSalad has `some` LowCal dressing, not `only`; SeafoodSalad has no `some Egg`.

**ValueSalad** ≡ Salad ⊓ `hasDressing some Dressing` ⊓ `hasMix some Meat` ⊓ `hasMix some Topping` ⊓ `hasVeggie some Vegetable`  
(Dressing + veg already on every Salad.)  
Answer: **PorkSalad, PowerMeatSalad, CheesySalad**  
(Pork + MeatTopping; Beef + Pork + MeatTopping; exactly 1 Meat + min 3 CheeseTopping). Beef/Chicken only force meat, not topping.

**LowCalSalad** ≡ Salad ⊓ `hasDressing some LowCalDressing` ⊓ `hasVeggie some Vegetable` ⊓ `hasMix only (Egg or Seafood)`  
Answer: **EggSalad, SeafoodSalad**  
(Egg: `only Egg` ⊆ Egg⊔Seafood, some LowCal; Seafood: `only Seafood`, `only LowCal` + Salad’s some Dressing ⇒ some LowCal). Healthy allows **Chicken**, so not ⊑ LowCal.

Exam table (parents with at least one inferred child):

| Parent Class | Inferred subclasses |
| --- | --- |
| MixVeggieSalad | SuperVeggieSalad, GreenSalad, EggSalad, HealthySalad |
| VegetarianSalad | EggSalad |
| ValueSalad | PorkSalad, PowerMeatSalad, CheesySalad |
| LowCalSalad | EggSalad, SeafoodSalad |

## 8. Exercise — Thai menu ontology

![[7_menu_dishes.png]]

Icons: leafy = no meat; chicken; pig = pork; prawn; fish; chili = spicy.

**Competency questions**

1. Stir-fried / soup / fried / spicy salad, but I cannot eat **this meat** — what can I order?  
2. Same cooking type, but I cannot eat **spicy** — what can I order?  
3. I want **this meat** — which dishes?  
4. I am **vegetarian** — what can I order?  
5. I am **allergic to seafood** — what can I order?

Dishes on the sheet are **individuals** (most specific answers). Types that need restrictions / reasoner grouping stay **classes**.

```
Thing
    Dish
        SpicySaladDish
        StirFriedDish
        SoupDish
        FriedDish
    Meat
        Chicken
        Pork
        Prawn
        Fish
```

| Property | Domain | Range |
| --- | --- | --- |
| hasCookingMethod / asserted parent | Dish | (the four dish kinds) |
| containsMeat | Dish | Meat |
| isSpicy | Dish | boolean |

Defined (Equivalent To) for CQs 3–5:

```
VegetarianDish  EquivalentTo
    Dish and (not (containsMeat some Meat))

SeafoodDish  EquivalentTo
    Dish and (containsMeat some (Prawn or Fish))

ChickenDish  EquivalentTo
    Dish and (containsMeat some Chicken)
```

Non-spicy stir-fry = `StirFriedDish and (isSpicy value false)`. Seafood allergy = not `SeafoodDish`. Attach each menu row as an individual of its cooking class, with `containsMeat` / `isSpicy` filled from the icons (ยำผักบุ้งกรอบ: SpicySalad + no meat + spicy; ผัดผักบุ้งหมูกรอบ: StirFried + Pork + spicy; ผักทอด: Fried + no meat + not spicy; …).

## 9. Exercise — GreenMart supermarket

Domain (condensed): company with branches; unique branch code; each branch belongs to **exactly one** company. Five department types: Dry Food, Household Goods, Fresh Produce, Beverages, Personal Care. Every branch **must** have ≥1 Dry Food and ≥1 Household Goods; the other three optional; **only** these five types; each department belongs to exactly one branch. Each department offers **≥5** product categories. Products: Food (Dry / Fresh / Beverage) vs Non-Food (Household Goods / Personal Care); Household Cleaning ⊑ Household Goods Product. A department stocks **only** its matching product group; Household Goods **must** stock ≥1 cleaning product. Each product: exactly one department, one category, one name, one **non-negative** price.

**Tasks:** classes + hierarchy; object/data properties (domain/range); class descriptions (OWL restrictions).

```
Thing
    SupermarketCompany
    Branch
    Department
        DryFoodDepartment
        HouseholdGoodsDepartment
        FreshProduceDepartment
        BeverageDepartment
        PersonalCareDepartment
    ProductCategory
    Product
        FoodProduct
            DryFoodProduct
            FreshProduceProduct
            BeverageProduct
        NonFoodProduct
            HouseholdGoodsProduct
                HouseholdCleaningProduct
            PersonalCareProduct
```

| Domain | Property | Range | Characteristics |
| --- | --- | --- | --- |
| SupermarketCompany | hasBranch | Branch | inverse of belongsToCompany |
| Branch | belongsToCompany | SupermarketCompany | Functional |
| Branch | hasBranchCode | string | Functional |
| Branch | hasDepartment | Department | inverse of belongsToBranch |
| Department | belongsToBranch | Branch | Functional |
| Department | offersCategory | ProductCategory | — |
| Department | stocks | Product | inverse of stockedBy |
| Product | stockedBy | Department | Functional |
| Product | hasCategory | ProductCategory | Functional |
| Product | hasName | string | Functional |
| Product | hasPrice | decimal | Functional |

```
Branch  SubclassOf
    belongsToCompany exactly 1 SupermarketCompany
    hasBranchCode exactly 1 string
    hasDepartment some DryFoodDepartment
    hasDepartment some HouseholdGoodsDepartment
    hasDepartment only (DryFoodDepartment or HouseholdGoodsDepartment
                        or FreshProduceDepartment or BeverageDepartment
                        or PersonalCareDepartment)

Department  SubclassOf
    belongsToBranch exactly 1 Branch
    offersCategory min 5 ProductCategory

DryFoodDepartment  SubclassOf
    Department
    stocks only DryFoodProduct

HouseholdGoodsDepartment  SubclassOf
    Department
    stocks only HouseholdGoodsProduct
    stocks some HouseholdCleaningProduct

FreshProduceDepartment  SubclassOf
    Department
    stocks only FreshProduceProduct

BeverageDepartment  SubclassOf
    Department
    stocks only BeverageProduct

PersonalCareDepartment  SubclassOf
    Department
    stocks only PersonalCareProduct

Product  SubclassOf
    stockedBy exactly 1 Department
    hasCategory exactly 1 ProductCategory
    hasName exactly 1 string
    hasPrice exactly 1 decimal
    hasPrice some decimal [>=0]
```

Disjoint the five department types; Food vs Non-Food; the five product groups.

## Takeaways

- Classify = inferred tree. Only **defined** classes receive inferred children.
- OWA: `some` veg toppings ≠ vegetarian until **closure** `only (union of those some)`.
- `only` without `some` includes **nothing**.
- Exam salad: Parent column = Equivalent To classes; use disjoint + `only` to see what is forced.
- Menu: cooking-type classes + meat/spicy properties; dishes as individuals.
- GreenMart: numbers in the prose become `exactly` / `min` / `some` / `only` / `[>=0]`.
